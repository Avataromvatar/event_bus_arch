### Итог и доказательства

Дополнен `doc/artifacts/plans/2026-11-22-event-address-analysis.md` разделом 6.

- V1 (`'$T'` только при пустых paths): отклонён. Не убирает зависимость от типа для pathless-событий, создаёт коллизии, ломает `Topic`/node identity, FSM/Scope/observability/transport; несовместим с текущей моделью «один типизированный node на topic».
- V2 (paths обязательны, тип не в адресе): когерентная channel-first архитектура, но требует redesign: идентичность узла `(channel, T)`, фильтрация по `data is T`, `currentData`/`haveListener`/`haveHandler` по типу, transport-десериализация по каналу, FSM-ключи, docs/tests. Оценка 8–12 человеко-дней.
- Альтернативы: A — типизированные `wireTypes` + обязательное покрытие в NATS/MQTT (~1 день, рекомендуется сейчас); E — `EventKey<T>` с явным стабильным адресом (3–5 дней, если нужна channel-first API); G — paths только на wire (больше работы, чем A).
